# Atlament 利用ガイド

このガイドは、Atlamentを初めて利用する人向けに、起動から初期設定、データ同期、各画面の使い方、問題が見つかった場合の対処を説明します。

## 起動する

### Windows

配布された `Atlament.exe` を起動します。初回起動時にWindowsの確認画面が表示された場合は、配布元が正しいことを確認してから続行してください。Atlamentの画面はアプリ内に表示されるため、通常の利用でブラウザを開く必要はありません。

### Android

端末のアプリ一覧からAtlamentを起動します。初回起動直後はデータ同期が完了していないため、`Application Settings` で初期設定を行います。

## 初期設定する

ナビゲーションから `Application Settings` を開き、次の順で設定します。

1. `GitHub Repository Source` に `Owner`、`Repository`、`Branch`、`Root Path` を入力して保存します。
2. リソース設定でワークアウト、マシンマスター、ジムマスターの保存場所を確認して保存します。
3. `Credential - GitHub Token` に対象リポジトリを読み書きできるGitHub Tokenと有効期限を入力し、`Update` を選択します。
4. `Operations - Remote Data Sync` の `Sync immediately` を選択します。

Tokenの値は保存後に画面へ再表示されません。期限切れや権限不足が表示された場合は、新しいTokenを入力して更新してください。

設定するリポジトリとブランチには、ワークアウトデータとマスターデータが存在する必要があります。組織や管理者から指定された値がある場合は、その値を使用してください。

## データを同期する

`Sync immediately` を選択すると、GitHub上のデータを取得し、Atlament内で表示できる形式へ変換します。処理中は読み込み中の表示が消えるまで待ってください。

- 成功表示: 同期が完了しています。
- 警告表示: 保存済みデータで継続できる場合や、確認が必要な参照が存在します。表示内容を確認してください。
- エラー表示: リポジトリ、ブランチ、Token、有効期限、通信状態を確認して再実行してください。

起動時にも、設定と認証情報が利用可能であれば自動同期が行われます。同期に失敗しても前回の正常なデータが残っている場合は、そのデータで閲覧を継続できます。

## Portalと各画面

`Portal` は各機能への入口です。アプリカードを選択して画面を開きます。各アプリのナビゲーションにあるPortalアイコンからPortalへ戻れます。

### Dashboard

最近のワークアウト、月間集計、前月との比較、負荷量・頻度・部位バランスのグラフを確認します。メインジムが未設定の場合、メインジムを前提とする重量指標は表示できません。

### Workout Domain

カレンダーまたは一覧からワークアウト日を選択し、その日のセッションと種目内容を確認します。ワークアウトデータは閲覧専用で、Atlamentからワークアウト記録自体を編集することはできません。

### Performance Detail

マシンを選択し、対象種目の履歴や推移を確認します。ワークアウトに未解決のマシン参照がある場合、その記録は警告付きで保持されます。

### Analytics

対象期間を選択し、負荷量や部位別集計などの長期傾向を確認します。期間を変更すると、表示中のグラフと表が更新されます。

### Resource Management

ジムマスターとマシンマスターの登録、更新、別名保存、論理削除、未解決参照の解決を行います。

- 新規登録: `新規作成` を選び、必要項目を入力して `登録する` を選択します。
- 更新: 対象行を開き、内容を変更して `更新する` を選択します。
- 別名保存: 編集画面の保存方法で別名保存を選び、`登録する` を選択します。
- 未解決参照: `未解決参照` から対象を選び、正しい登録情報を選択して `解決する` を選択します。

保存時に競合が表示された場合、別の操作でGitHub上のマスターデータが更新されています。再読み込みまたは再同期して最新状態を確認してから、必要な変更をやり直してください。

### Application Settings

接続先、リソース、タイムアウト、GitHub Token、同期状態を管理します。通常の閲覧画面が利用できない場合も、`Application Settings` から設定の確認と再同期を行えます。

## テーマを切り替える

ナビゲーション下部のテーマアイコンでLight / Darkを切り替えます。選択したテーマは保存され、Portalと各アプリで共通して使用されます。

## 修復が必要な場合

同期したリソースに形式不備などがある場合、`Resource Management` の `修復が必要なデータ` に表示されます。

1. 対象リソースを開き、問題と診断情報を確認します。
2. `下書きを作成` を選択します。
3. `修復内容` の必須項目を入力または選択します。
4. 下書きを保存し、`修復内容を確認` でリソース全体を検証します。
5. エラーがなく、警告の内容も許容できることを確認して修復を実行します。

下書きは端末内だけに保存され、GitHubへは自動送信されません。元のリソースが別操作で更新された場合、下書きは古い状態となり、そのままGitHubへ反映できません。最新のリソースを読み直して新しい下書きを作成してください。

修復後の保存に成功しても、再同期や画面反映だけが失敗する場合があります。その場合は同じ修復を繰り返さず、表示された結果を確認して `Application Settings` から再同期してください。

## エラーや警告が表示された場合

- 初期設定未完了: `Application Settings` でリポジトリ、リソース、認証情報を設定します。
- 認証情報の期限切れ・無効: 有効なGitHub Tokenと期限を登録し直します。
- リポジトリが見つからない: `Owner`、`Repository`、`Branch`、`Root Path` とTokenの権限を確認します。
- 同期失敗: 通信状態を確認して `Sync immediately` を再実行します。前回データで継続中と表示される場合は閲覧できますが、表示内容は最新ではない可能性があります。
- 未解決参照: `Resource Management` で既存のジムまたはマシンへ関連付けるか、新しいマスター情報を登録します。
- 修復が必要: `修復が必要なデータ` から対象を確認します。`元データ` は診断用であり、直接編集する画面ではありません。

解決できない場合は、画面に表示されたエラーコード、対象リソース、発生した操作を控えて管理者へ連絡してください。GitHub Tokenそのものは共有しないでください。
