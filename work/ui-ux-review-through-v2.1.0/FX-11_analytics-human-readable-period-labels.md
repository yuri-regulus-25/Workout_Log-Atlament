# FX-11 Analytics期間表記を人間向けにする

## 概要

Analyticsの期間プリセットで使用している `7d` / `28d` / `3m` / `6m` のような内部値・開発者向け省略表記を、そのままユーザーUIへ露出しない。

## 現在の表示

確認画像: `Codex 画像 2026年9月2日 01_08_35.png`

```text
7d
28d
Month
3m
6m
All
```

## 期間の意味

032.mdでユーザーから明示された意味は次のとおり。

```text
7d    = 直近7日
28d   = 直近28日
Month = 当月（暦月）
3m    = 直近3か月
6m    = 直近6か月
All   = 全期間
```

`Month` は「直近1か月」ではない。

したがって `Month` を `1m` へ置換してはならない。期間計算の意味が変わる。

## 確定している要求

- `d` / `m` の短縮表記をユーザーUIからなくす。
- 内部値やAPI・Query Parameterを変更する要求ではない。
- 表示ラベルだけを人間が読んで意味を理解できる表記にする。
- `Month` は現在の暦月を意味することが誤認されない表記にする。

## 表示候補

会話中では次の候補が提示された。

英語寄せ:

```text
7 Days
28 Days
This Month
3 Months
6 Months
All
```

日本語寄せ:

```text
7日間
28日間
今月
3か月
6か月
全期間
```

**どちらを採用するかは031〜033では確定していない。**

## 実装方針

期間計算ロジックや内部識別子と表示文言を分離する。

概念例:

```ts
{ value: '28d', label: '28日間' }
```

これは構造例であり、実際の型・実装箇所はRepositoryの現行実装へ合わせる。

## 受入条件

1. ユーザーが見る期間選択肢に `7d` / `28d` / `3m` / `6m` が表示されない。
2. 当月条件が直近1か月と誤認されない。
3. 各期間の計算結果は変更前と同一である。
4. 内部値をUI文言変更のためだけに変更しない。
