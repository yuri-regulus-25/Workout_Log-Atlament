# FX-03 Dashboardセット数推移の期間スコープ統一

## 概要

Dashboardの「セット数推移」が過剰に長い期間を表示しているため、同じDashboard内の「ボリューム推移 - メインジム」と同じ期間スコープへ統一する。

## 確認した現状

確認画像:

`Codex 画像 2026年9月2日 00_57_38.png`

画像では「セット数推移」に多数のWorkoutが棒グラフとして表示されており、横方向の情報密度が高い。

同じ画面内には「ボリューム推移 - メインジム」があり、ユーザーはセット数推移について明示的に次を要求した。

> **「ボリューム推移 - メインジム の範囲と同じ期間でいいです。こんなに要らない。」**

## 確定している要求

「セット数推移」の対象期間を、同じDashboard内の「ボリューム推移 - メインジム」と同一にする。

```text
ボリューム推移 - メインジム
└─ 対象期間: Dashboardで現在採用している期間

セット数推移
└─ 対象期間: 上記と同じ
```

## 不要とされた拡張

この指摘を解消するために、次を新設する必要はない。

- セット数推移専用の期間Filter
- `直近10回` / `直近30日` / `全期間` 等の追加切替UI
- Analyticsへの新しい誘導
- Dashboard専用の新しい分析機能

`016.md` では直近N件等の案も提示されたが、`017.md` でユーザーがより具体的に **「ボリューム推移 - メインジムと同じ期間」** と指定したため、こちらを優先する。

## UX上の目的

同じDashboard上で、同一期間について次を横断的に読めるようにする。

- Volumeの推移
- Set数の推移

期間Scopeを揃えることで、表示量を抑えるだけでなくChart同士の比較可能性を維持する。

## 受入条件

1. 「セット数推移」が「ボリューム推移 - メインジム」と同じ対象期間を使用する。
2. セット数推移だけが全履歴相当を表示する状態を解消する。
3. 期間を揃えるための不要な追加Filter UIを新設しない。
4. 既存のChart内容・Set数計算そのものは、この指摘だけを理由に変更しない。
5. Windows / Androidで同じ期間Scopeを使用する。

## 未確定事項

「ボリューム推移 - メインジム」が内部的にどの期間決定Logicを使用しているかは、この会話資料では確認していない。

実装時はRepository上の現行Logicを確認し、Set Count側が同じScopeを参照する形で実装する。期間値を推測して別途固定しない。

## 位置づけ

既存Dashboardの情報設計改善。Correctness blockerではない。
