# FX-25 モバイル共通ナビゲーション UX 改善

## 対象

Android を含む、縦長・狭幅 Viewport での共通 Header / Navigation。

## 背景

現状は Header がコンテンツとともにスクロール対象となるため、縦方向へスクロールすると共通ナビゲーションへの導線が画面外へ消える。

また、狭幅画面では Navigation Drawer をハンバーガーボタンから開けるが、タッチ端末で自然なジェスチャーによる導線も追加したい。

## 改善案

### 1. Header の固定表示

狭幅・縦長画面では、共通 Header をスクロールアウトさせず Viewport 上部へ固定表示する。

- コンテンツのみを縦方向へスクロールできること。
- Header にある既存のナビゲーション導線は維持すること。
- 実装時は Header 高さ、スクロールコンテナ、z-index、safe area、Android WebView での挙動を確認すること。
- 単純な `position: fixed` の採用を前提とせず、`sticky` を含めて既存レイアウトとの整合性から実装方式を決定すること。

### 2. 左端スワイプによる Navigation Drawer 表示

既存のハンバーガーボタンは維持したうえで、画面左端付近から右方向へスワイプした場合にも同じ Navigation Drawer を開けるようにする。

- スワイプ専用の別 Navigation を作らず、ハンバーガーボタンと同一の Drawer 状態を操作すること。
- 画面全域の右スワイプを対象にせず、左端付近から開始したジェスチャーに限定すること。
- 横方向操作を持つグラフ、カルーセル、Workout 操作等とのジェスチャー競合を避けること。
- Drawer を閉じる操作は既存 UX と整合させること。

## 設計上の位置付け

本項目は v3.0.0 の Visual Tone / App Shell 再構築そのものではなく、現行 UI にも適用可能な共通 UX 改善として扱う。

v3.0.0 で Header / Navigation / Application Surface を再構築する場合も、以下の操作契約は引き継ぐ。

1. 狭幅・縦長画面では共通 Header が常時アクセス可能であること。
2. Navigation Drawer は明示的なボタン操作に加え、左端からのスワイプでも開けること。
3. 複数の入力手段が存在しても、操作対象となる Navigation の状態は一つであること。

## 状態

UX 改善候補。実装方式・適用バージョンは未確定。
