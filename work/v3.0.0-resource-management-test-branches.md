# v3.0.0 Resource Management Human Test Branches

この文書は、Resource Management の Human Test を行うための試験用ブランチ一覧と操作手順です。初めて Atlament を触るテスターでも、この文書だけで「どのブランチで何を確認するか」が分かる粒度で記載しています。

## 共通情報

- 共通基底ブランチ: `release-3.0.0`
- 共通基底SHA: `fdf34cdee5b464b2275ec6f60107d006ccc07367`
- 試験用ブランチはすべて `release-3.0.0` から直接作成しています。
- 試験用ブランチ同士は親子関係ではありません。
- 各ブランチの差分は試験用データだけです。製品コードは変更していません。

## 試験を始める前の共通手順

各試験ブランチで、最初に以下を行ってください。

1. Repository を対象ブランチへ切り替えます。
   - 例: `git switch test-v3.0.0-machine-edit-light-secondary`
2. Windowsアプリが未起動の場合は、Windows版を起動します。
   - ビルドが必要な場合: `npm run build:windows`
   - 起動するexe: `dist-windows/Atlament-v3.0.0-win-x64/Atlament.exe`
3. Atlament の画面で `Application Settings` を開きます。
4. `GitHub Repository Source` の入力欄を以下に設定します。
   - `Owner`: `yuri-regulus-25`
   - `Repository`: `Workout_Log-Atlament`
   - `Branch`: 今から試験するブランチ名
   - `Data Root`: `data`
5. `Save` を押します。
6. `Resource Data` に以下の3行があることを確認します。
   - `WORKOUT` / `workouts/` / `directory` / `Required`
   - `MACHINE_MASTER` / `master/machines.json` / `file` / `Required`
   - `GYM_MASTER` / `master/gyms.json` / `file` / `Required`
7. `リモートデータ同期` の `Sync immediately` を押します。
8. 同期完了後、Portal またはNavigationから `Resource Management` を開きます。
9. 各ブランチの「Theme条件」に合わせて、Light/Dark と Primary/Secondary Color を設定してから見た目を確認します。

補足:

- `work\Windows_Settings_api\apply-windows-settings.ps1 -Sync` を使う場合は、先に `work\Windows_Settings_api\settings.json` の `configuration.repository.ref` を試験対象ブランチ名へ変更してください。
- そのまま実行すると `master` を参照するため、今回の試験データは読み込まれません。

## 試験後の注意

Resource Management の更新・解決・修復・メインジム変更を実行すると、試験ブランチ上にGitHub WriterによるCommitが作成される場合があります。

- そのCommitもHuman Testの確認対象です。
- 再試験する場合は、各ブランチの「試験開始時HEAD」へ戻してください。
- 戻す対象SHAは各ブランチの説明に記載しています。
