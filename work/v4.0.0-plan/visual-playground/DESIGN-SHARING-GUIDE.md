# Atlament v4 ビジュアル検討・共有ガイド

## この文書について

この文書は、Atlament v4 の見た目を別の LLM や人間と検討するための共有資料である。

実装を読まなくても、次の内容が分かることを目的としている。

- どのような見た目を目指しているか
- 何を使って実現しているか
- 画面がどのような層で構成されているか
- 現在どの数値を基準にしているか
- どこまで決まっていて、何が未決定か

ここでいう **Pre-Fix** は「最終決定」ではなく、壁打ちや比較の出発点として一度固定した状態を指す。

## まず30秒で分かる要約

Atlament v4 では、暗い背景の上に次の3種類の表現を組み合わせる案を検討している。

1. **Ambient Particle**
   画面下部から上へ浮かぶ、非常に小さな光の粒。背景に奥行きと動きを与える。
2. **Glass**
   情報を載せる、固定された安定面。今回は強い曇りガラスではなく、低いぼかしと薄い輪郭、反射を中心にしている。
3. **Plasma**
   ドラッグや接触に反応する液体状の操作面。動かせる要素、触れる要素の候補として使う。

基本仮説は、**「Glass は安定した情報面、Plasma は動かせる操作面」**という役割分担である。

背景そのものには明るさや緑色を足していない。緑色は Particle、下部の淡い環境光、Glass の反射、Plasma の縁や発光など、光として見える場所へ限定している。

## これは製品画面ではない

現在の実装は、デザインを触って比較するための独立した実験環境である。

- Dashboard や Workout 画面の完成形ではない。
- 実データ、Backend、GitHub、ファイル保存機能とは接続していない。
- 既存製品の画面遷移や MPA 構成には組み込んでいない。
- Windows / Android の製品 UI にもまだ反映していない。
- ここで選んだ数値を、そのまま最終 Design Token とすることは決まっていない。

## 用意している3つの比較画面

### A. Glass

大・中・小のカード、ナビゲーション風の横長部品、ボタン、状態表示用の小部品を並べている。

Particle は Glass の後ろを通過する。これにより、Glass 越しに見たときの次の変化を確認できる。

- 粒がどの程度ぼけるか
- 透明感を残しながら文字を読めるか
- 反射や発光がうるさくないか
- 面の内側と外側で奥行きが変わって見えるか

### B. Plasma

複数の液体状の面をドラッグできる。近づける、接触させる、結合させる、引き伸ばす、再び離す、という一連の動きを確認する画面である。

固定された操作部品も置き、液体として動かす要素と動かさない要素の差を確認できるようにしている。

### C. Composition

Particle、Glass、Plasma を同時に表示する。

個別には良く見えても、全部を重ねると騒がしくなる可能性がある。そのため、最終的な役割分担と情報の読みやすさを確認するための画面としている。

## 使用している技術と採用理由

| 技術・ライブラリ | バージョン | 何に使っているか | 採用理由 |
|---|---:|---|---|
| React | 19.2.8 | 画面部品と状態管理 | 3つの比較画面と調整パネルを小さな部品に分けやすい |
| TypeScript | 6.0.3 | 設定値の型定義 | JSON、スライダー、各描画処理で同じ設定構造を共有できる |
| Vite | 8.2.1 | 開発サーバーとビルド | 独立した試作画面を素早く起動・更新できる |
| tsParticles | 4.4.0 | 背景の光の粒 | 下端から粒を発生させる仕組み、移動、寿命、透明度、発光をまとめて制御できる |
| `@tsparticles/react` | 4.4.0 | tsParticles と React の接続 | React の画面部品として Particle 用 Canvas を管理できる |
| Plasma UI | 0.7.0 | 液体状の操作面 | 接触、結合、伸び、分離、ドラッグを独自実装せず試せる |
| CSS | ブラウザー標準 | Glass 表現 | Glass は専用ライブラリを使わず、透明度、ぼかし、反射、影を直接調整したい |

### tsParticles をどのように使っているか

tsParticles は、Canvas と呼ばれる専用の描画面に Particle を描くライブラリである。

今回は、画面下端全体を発生源にしている。そこから緑系の小さな粒を上方向へ移動させ、左右へ少し散らし、最後に透明にして消している。

下端から粒を発生させる機能を使うため、機能を絞った軽量版ではなく、発生源機能を含む Full bundle を採用している。

現在の Pre-Fix では次の動作になる。

- 最初に 65 個を配置する。
- 0.15 秒ごとに 5 個を追加する。
- 粒の大きさは約 0.8〜1.35 px。
- 1個の粒は最大48秒間存在する。
- 45.6秒間は最大透明度を保つ。
- 最後の2.4秒で徐々に透明になり、透明度0で破棄する。
- 横方向の散らばりは、実装上の上限である35度まで使う。

以前は粒ごとに寿命がランダム化され、まだ見えている状態で突然消えることがあった。現在は、寿命を透明度の減少へ一本化し、必ず透明になってから消すようにしている。

### Glass をどのように作っているか

Glass に専用ライブラリは使っていない。ブラウザー標準の CSS を組み合わせている。

- 半透明の色の重なりで面を作る。
- `backdrop-filter` で面の後ろをぼかし、彩度を調整する。
- 上側に薄い白い反射を置く。
- 内側の明るい線、外側の緑の光、黒い影を重ねる。
- 同じ基本表現をカード、ボタン、チップなど異なる形へ適用する。

Pre-Fix はぼかしが 2 px と非常に弱い。そのため、典型的な曇りガラスというより、薄く色と反射が乗った透明面に近い。

### Plasma UI をどのように使っているか

Plasma UI は、WebGL2 という GPU 描画機能を使って液体状の面を描く React ライブラリである。

各 Plasma 面は通常の HTML 要素として配置するが、実際の液体表現は画面全体を覆う別の Canvas に描画される。面をドラッグして近づけると、ライブラリが接触、結合、引き伸ばし、分離を計算する。

弾力を直接表す単独設定はないため、主に粘り気を表す `viscosity` と、伸び方を表す `stretch` の組み合わせで感触を調整している。

## 画面の重なり方

画面は、おおむね次の順序で背面から前面へ重なっている。

```text
最前面  ヘッダー、画面切替、設定パネル
   ↑    説明文、Glass の内容、Plasma の操作対象
   │    Glass の半透明面
   │    Particle 用 Canvas / Plasma 用 Canvas
   ↓    暗い背景、薄い格子、下部の環境光
最背面
```

Particle と Plasma は別々の Canvas に描かれる。したがって、Particle が Plasma の内部で本当に屈折して見えるわけではない。Glass はブラウザーの背景ぼかしを使うため、Glass の後ろを通る Particle はぼかして表示できる。

## 設定値の保存と共有

画面右側の設定パネルでは、各値をスライダーで変更すると即座に見た目へ反映される。

- 現在値を JSON としてコピーできる。
- JSON を貼り付けて同じ状態を復元できる。
- 名前を付けてブラウザー内へ保存できる。
- 「Reset default」で Pre-Fix へ戻せる。

ブラウザー内の保存には LocalStorage を使っている。これは同じブラウザー内だけの保存であり、サーバーやほかの端末とは同期しない。

## 現時点で分かっている制約

### Particle

- Full bundle を使うため、単純な CSS アニメーションより JavaScript の量が増える。
- Pre-Fix は発生量と寿命がともに大きく、状況によっては同時に非常に多くの粒が存在する。性能と「星空に見えないか」は要確認である。
- 動きを減らす設定が OS で有効な場合は、Particle の再生と移動を停止する。

### Glass

- `backdrop-filter` に対応しないブラウザーでは、後ろの Particle をぼかす効果を確認できない。
- `borderBrightness` という設定値は存在するが、現在の CSS には接続されていない。そのため、この値を変えても見た目は変わらない。

### Plasma

- Plasma 用 Canvas は画面全体を覆う。特定カードの中だけへ描画範囲を限定する使い方ではない。
- Particle、Glass、Plasma は別の描画層にあるため、Plasma が Particle や Glass を実際に屈折させることはできない。
- WebGL2 が使えない場合は簡易な CSS 表現へ切り替わり、液体の陰影、屈折、結合の見た目は完全には評価できない。
- 主にデスクトップ向けであり、小さな画面や低性能端末での最終評価はまだ行っていない。

## 壁打ちで確認したい論点

以下は未決定であり、別の LLM や人間から意見を得たい項目である。

1. Particle の密度と発生頻度が高すぎず、星空やノイズに見えないか。
2. 48秒の寿命と、最後の2.4秒だけで消える設定が自然か。
3. 1 px 前後の Particle が、高解像度画面でも存在感を保てるか。
4. 2 px の Glass blur は弱すぎないか。それとも透明感を残す方向として適切か。
5. Glass の border を2%まで薄くしたとき、背景によって輪郭を見失わないか。
6. Glass を情報面、Plasma を操作面とする役割分担が直感的か。
7. Plasma の色面を透明にし、縁、霜、屈折、発光を中心にした見せ方が成立するか。
8. Particle と Plasma が別 Canvas である制約を許容できるか。
9. 全部を重ねた Composition が、落ち着きと未来感を保てているか。
10. この Pre-Fix から Production Design Token へ昇格させる値と、画面ごとに調整すべき値をどう分けるか。

## ローカルで確認する方法

Node.js 22 以上を用意し、Repository root で次を実行する。

```powershell
npm ci
npm run dev -w @workout-lab/v4-visual-playground
```

配布可能な静的ファイルを生成できるか確認する場合は、次を実行する。

```powershell
npm run build -w @workout-lab/v4-visual-playground
```
