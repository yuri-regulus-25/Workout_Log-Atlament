## UT-06 — Android Draft保存先の想定と実機の差異

### 判明した事実

UT-06 Corrupted Draftの試験で、adbからAndroid実機上のDraftファイルを意図的に破損させる際、事前に想定していた保存先と実機で実際に確認できた保存先に差異があった。

事前に想定していた保存先:

`files/data/recovery/drafts/`

Android実機で実際に確認できた保存先:

`files/recovery/drafts/`

Android package:

`jp.yuri_regulus_25.atlament`

実機でDraftファイルを発見した後、内容を意図的に `THIS_IS_A_BROKEN_DRAFT` 相当へ破損させ、Corrupted Draftとして検出・隔離できること自体は確認済み。

### 現時点の判定

**UT-06本来の試験結果はPASSのままとする。**

Draftの保存・読込・破損検出・影響分離そのものは正常に動作していたため、このPath差異だけを理由にUT-06をCorrectness NGへ変更しない。

一方で、この差異を単なる試験手順上の思い違いとして処理してはならない。

設計・Windows実装・Android実装の間でDraft Storeの配置規約が意図せずずれている可能性があるため、**設計整合性の調査対象として残す。**

### 調査する内容

1. Windowsの `RecoveryDraftStore` が実際にどのApp Data配下へ保存しているか確認する。
2. Androidの `RecoveryDraftStore` が実際にどのApp Data配下へ保存しているか確認する。
3. Recovery設計資料にDraft保存先の物理PathまたはLogical Pathに関する規約が存在するか確認する。
4. WindowsとAndroidの差異が、各OSのnative app-data rootを基準とした意図的なPlatform差なのか確認する。
5. `data/recovery/drafts` と `recovery/drafts` の差が単なるroot表現の違いなのか、Logical Storage Hierarchyそのものの不一致なのか確認する。
6. 意図的なPlatform差で仕様上問題がない場合は、その理由と各Platformの実際の確認Pathを開発・UT手順へ明記してCloseする。
7. Logical Storage Hierarchyの不一致だった場合は、設計と実装のどちらを正とするか決め、必要な修正を行う。

### 設計上の既知条件

現在保持しているRecovery設計では、Draftは次の性質を持つ。

- AFのnative app-data配下へ保存する。
- Git Repositoryには保存しない。
- BrowserのlocalStorageには保存しない。
- Device Localであり、端末間同期は行わない。

この条件だけを見る限り、Android実機の `files/recovery/drafts/` が直ちに設計違反であるとは断定できない。

したがって重大度は現時点で **調査対象 / 設計整合性確認** とし、UT-08 Path RelocationのようなFreeze blockerとは分離する。

### 調査完了条件

次のいずれかまで確認できた時点でCloseできる。

- Platformごとの保存先差異が意図されたものであり、設計・実装・UT手順の説明が一致した。
- 意図しない差異であることが判明し、設計または実装を修正して保存先規約が一致した。

どちらの場合でも、今後adb等でDraftを直接確認する際に保存先を推測しなくて済むよう、実際の確認手順を資料へ残す。
