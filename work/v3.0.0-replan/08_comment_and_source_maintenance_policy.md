# コメントおよびソース保守方針

## 1. 基本方針

コメントは保守対象となるソース資産として扱う。

既存コメントを、リファクタリングでコードを移動・整理するという理由だけで削除してはならない。

## 2. 既存コメント

- 実装が変わっても内容が正しい場合は維持する。
- 実装変更により不正確になる場合は、新しい実装に合わせて更新する。
- 移動した責務を説明するコメントは、必要に応じて責務の移動先へ移す。
- コメントアウトされたコードは通常のソース整理対象として変更・削除してよい。

## 3. 新規コメント

次の内容はコメント追加候補とする。

- 責務の境界
- 非自明な処理
- 設計上の制約
- 一見不要に見える処理を残す理由
- Platform間で挙動を一致させる理由
- 外部APIの制約に起因する処理
- 「何をしているか」だけではコードから読み取れない「なぜ」

コードを日本語へ言い換えただけのコメントは増やさない。

## 4. 言語

コメントは原則として日本語とする。

API名、型名、クラス名、ライブラリ名、規格名等の技術固有名詞は英語表記を維持してよい。

日本語文の中へ不要な英単語を混在させず、自然な日本語で記述する。

## 5. 命名

既存命名を無理由に全面変更しない。

責務分離により既存名が実態と合わなくなる場合は、責務を具体的に示す名称へ変更する。

`Manager`、`Helper`、`Util` 等を使用する場合は、その名称だけで責務を曖昧にしていないか確認する。
